## 1. Scope

External configuration controls paths, services, logging and timeouts. Rules, knowledge schemas and Planner decisions remain versioned in code.

Core reads environment variables when constructing the runtime. Environment changes require a new execution. There is no rule configuration file for the analyst to edit.

## 2. Core variables

These defaults apply when running Core directly. Timeouts are expressed in seconds.

| Variable | Default | Purpose |
| --- | --- | --- |
| `CENTAURUS_WORKSPACE` | `/workspace` | Persistent root for investigations and logs. |
| `CENTAURUS_LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR` or `CRITICAL`. |
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Inference service. |
| `OLLAMA_MODEL` | `qwen3:4b` | Requested model. |
| `OLLAMA_TIMEOUT` | `60` | Base Ollama client timeout. |
| `OLLAMA_INTERPRETATION_TIMEOUT` | Inherits `OLLAMA_TIMEOUT` | LLM #1 interpretation. |
| `OLLAMA_ANALYST_ASSISTANCE_TIMEOUT` | `300` | LLM #2 assistance; independent of the base timeout. |
| `OLLAMA_ANALYST_ASSISTANCE_NUM_CTX` | `8192` | LLM #2 context window. |
| `OLLAMA_ANALYST_ASSISTANCE_NUM_PREDICT` | Unset | Optional LLM #2 generation limit. |
| `CENTAURUS_WHOIS_TIMEOUT` | `10` | WHOIS adapter. |
| `CENTAURUS_RDAP_TIMEOUT` | `10` | RDAP adapter. |
| `CENTAURUS_CRTSH_TIMEOUT` | `30` | crt.sh adapter. |
| `CENTAURUS_DNSRECON_TIMEOUT` | `120` | DNSRecon adapter. |
| `CENTAURUS_SUBLIST3R_TIMEOUT` | `180` | Sublist3r adapter. |
| `CENTAURUS_THEHARVESTER_TIMEOUT` | `300` | TheHarvester adapter. |

Required text settings cannot be empty. Timeouts must be positive numbers; context and generation limits must be positive integers. An absent or blank `OLLAMA_ANALYST_ASSISTANCE_NUM_PREDICT` omits that limit from the request. The log level is normalized to uppercase.

Rejected configuration prevents an investigation from starting and the CLI exits with code `1`.

## 3. Git + Docker

Bootstrap uses `CENTAURUS_DATA_ROOT`; when unset, it uses `${XDG_DATA_HOME:-$HOME/.local/share}/centaurus`. It creates `compose.env` with mode `0600` and the persistent paths:

| Deployment variable | Value generated by bootstrap |
| --- | --- |
| `CENTAURUS_OLLAMA_HOST_DIR` | `<data-root>/ollama` |
| `CENTAURUS_WORKSPACE_HOST_DIR` | `<data-root>/workspace` |

These are host paths. Inside Core, Compose fixes `CENTAURUS_WORKSPACE=/workspace` and `HOME=/tmp/centaurus`. Exporting another internal path on the host does not change these literal values.

Compose defaults to `http://centaurus-ollama:11434` and sets the default interpretation timeout to `60`. Changing only `OLLAMA_TIMEOUT` therefore **does not change** `OLLAMA_INTERPRETATION_TIMEOUT` in this mode. Set them separately to change both.

After bootstrap, the Git + Docker administrator can add variables interpolated by Compose to the generated `compose.env`. Preserve its two paths and always select that file with `--env-file`. Exported shell variables may override file values; inspect the environment when diagnosing differences.

Bootstrap regenerates `compose.env`. Keep a copy of custom settings before running it again and check which options the selected version supports. Follow [`DEPLOYMENT_GIT_DOCKER.en.md`](DEPLOYMENT_GIT_DOCKER.en.md) for startup, shutdown and logs.

Changing `OLLAMA_MODEL` does not download or validate a new model: provisioning and model identity belong to the supply chain. Ollama mounts the model store read-only during normal operation.

## 4. OVA and USB

The appliance uses managed configuration verified by its runtime broker. The broker clears the inherited environment and checks the identities of Compose, the environment file and the Core image.

Settings exported by the analyst do not automatically reach the container. Changing protected files may block startup because of an integrity mismatch. Appliance administrators own this maintenance; normal operation remains `centaurus` from a TTY.

## 5. Logs and diagnosis

Operational logging writes to `<workspace>/logs/centaurus.log`, separate from knowledge artifacts. It uses UTF-8, UTC timestamps and 5 MiB rotation with three backup files.

In Git + Docker, the host workspace is the generated path beneath the data directory; on the appliance it is `/workspace`. Logs may contain operational investigation context: protect permissions and review their contents before sharing them.

An LLM #2 timeout does not invalidate the persisted deterministic report. Increasing that timeout can allow more inference time, but cannot guarantee sufficient memory or a valid response. Context and generation limits also affect resource consumption.
